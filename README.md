# Proxy Bypass for Firefox

Расширение для Firefox: выбранные вкладки и выбранные сайты открываются **напрямую**,
минуя прокси, настроенный в браузере. Всё остальное продолжает ходить через прокси
как обычно.

## Зачем

Российские сайты — госуслуги, банки, ГИС ЖКХ, региональные порталы, личные кабинеты,
служебные системы — нередко блокируют запросы, пришедшие с IP прокси, особенно с
зарубежных. Обычно в такой ситуации приходится выключать прокси целиком и терять его
для всего остального.

Здесь решение локальное: прокси отключается только для тех вкладок и сайтов, которые
вы явно перечислили. Рабочие сессии, обновления, почта и всё прочее продолжают идти
через прокси.

## Как работает

Решение принимается в фоновом скрипте в обработчике `proxy.onRequest`. Событие
срабатывает до всех `webRequest`-событий и получает `tabId` вкладки, поэтому
исключение действует на **все** её запросы: подресурсы, iframe, `fetch`/XHR,
WebSocket, картинки, шрифты.

Дальше два исхода:

| Запрос | Что возвращается | Что делает Firefox |
| --- | --- | --- |
| Вкладка или сайт в списке | `[null]` | цепочка прокси обрывается, соединение напрямую |
| Всё остальное | `undefined` | используется прокси по умолчанию (ручной, PAC, автоопределение, авторизация) |

Почему для прямого соединения именно `[null]`, а не `{type: "direct"}`: если в Firefox
уже настроен прокси, `direct` означает для него «использовать прокси по умолчанию».
Принудительно обойти настроенный прокси можно только массивом, который оканчивается
на `null`.

Расширение не вызывает `proxy.settings.set`, поэтому настройки прокси в
`about:preferences` остаются нетронутыми — меняется только решение по каждому запросу.

Список вкладок живёт до перезапуска браузера: идентификаторы вкладок при следующем
старте другие. Для постоянных исключений нужны правила сайтов — они хранятся между
сессиями. Закрытая вкладка убирается из списка сама.

## Что писать в фильтры

Добавить правило можно двумя способами:

- иконка в панели → «Всегда обходить этот сайт» — добавит хост текущей страницы;
- «Настройки расширения» → «Правила сайтов» → поле ввода.

Фильтр — одна строка. Что означает:

| Фильтр | Что означает |
| --- | --- |
| `example.com` | хост и **все его поддомены**: `example.com`, `a.example.com`, `a.b.example.com` (но не `notexample.com`) |
| `*.local` | только поддомены: подходит `printer.local`, не подходит `local` |
| `192.168.*` | шаблон хоста |
| `localhost:8080` | хост с портом |
| `https://bank.ru` | префикс URL: `https://bank.ru/login` подходит, `http://bank.ru/` — нет |
| `example.com/api` | то же, что `*://example.com/api` — префикс по любой схеме |
| `*://*.cdn.net/*` | шаблон URL |

Правило с `/` или со схемой сравнивается как префикс (совпадает сам адрес и всё после
него через `/`, `?`, `#`, `:`). Правило с `*` — как шаблон. Правило-хоста без `*`
захватывает поддомены. IDN-домены (`пример.рф`) приводятся к punycode сами.

Примеры набора:

```
gosuslugi.ru
*.gosuslugi.ru
192.168.*
localhost:8080
https://sberbank.ru
```

Проверить, что правило сработало, можно в настройках расширения: там есть счётчики
«напрямую» / «через прокси» и журнал решений с указанием причины по каждому запросу.
